## Теория

### 1. Что такое граф?
Граф — это набор **вершин** (узлов) и **ребер** (связей между ними).
Примеры: карта городов и дорог, социальная сеть (люди и дружбы), интернет (компьютеры и кабели).
Граф может быть **ориентированным** (дороги с односторонним движением) и **неориентированным** (двусторонние связи).

### 2. Способы представления графа
1. **Матрица смежности:** двумерный массив `bool matrix[N][N]`. Быстрая проверка связи (O(1)), но требует много памяти (O(N²)).
2. **Список смежности:** массив списков (или векторов). `std::vector<std::vector<int>> adj`. Экономит память (O(V + E)), используется в 90% задач.

### 3. Обход в глубину (DFS — Depth-First Search)
Алгоритм идет по графу как можно дальше по одной ветке, пока не упрется в тупик, а затем возвращается назад (backtracking).
**Структура данных:** **Стек** (LIFO). Можно реализовать рекурсивно (системный стек) или итеративно.
**Применение:** Поиск выхода из лабиринта, проверка на циклы, топологическая сортировка.

### 4. Обход в ширину (BFS — Breadth-First Search)
Алгоритм исследует граф слоями: сначала всех соседей первого уровня, затем соседей соседей и т.д.
**Структура данных:** **Очередь** (FIFO).
**Применение:** Поиск кратчайшего пути в невзвешенном графе, поиск в социальных сетях (друзья друзей).

### 5. Инженерный вывод: когда использовать?
* **DFS:** когда нужно просто проверить связность графа или найти любой путь.
* **BFS:** когда нужно найти **кратчайший** путь (по количеству ребер).

### 6. Базовый синтаксис (список смежности)
~~~cpp
#include <vector>

int V = 5; // Количество вершин
std::vector<std::vector<int>> adj(V);

// Добавление ребра (например, 0-1)
adj[0].push_back(1);
adj[1].push_back(0); // Если граф неориентированный
~~~

## Практика

В папке `src/` находятся три файла:
* `custom_bfs_dfs.cpp` — заготовка для **собственной реализации** обхода графа (DFS и BFS).
* `stl_graph.cpp` — пример решения практической задачи (поиск пути в лабиринте/графе) с использованием стандартных `stack` и `queue`.
* `benchmark_graph.cpp` — замер скорости: **поиск пути в графе с помощью BFS против полного перебора (DFS)** (на примере поиска выхода).

Выполните задания из [TASKS.md](TASKS.md), чтобы получить практические результаты.

### Предполагаемые результаты бенчмарков
В задаче поиска **кратчайшего** пути (например, в лабиринте) BFS всегда находит выход быстрее (исследует меньше вершин), чем DFS, который может уйти в тупик и долго возвращаться. 
*Вывод:* для поиска кратчайшего пути используйте BFS (очередь). Для проверки связности — DFS (стек).
