## Теория

### 1. Идея бинарного дерева поиска (BST)
В массиве поиск занимает O(n), в хеш-таблице — O(1), но хеш-таблица не хранит элементы в отсортированном порядке.
Бинарное дерево поиска (Binary Search Tree) решает обе задачи: обеспечивает быстрый поиск за O(log n) и хранит данные отсортированными.

**Свойства BST:**
1. У каждого узла есть не более двух потомков (левый и правый).
2. Все значения в левом поддереве **меньше** значения узла.
3. Все значения в правом поддереве **больше** значения узла.

### 2. Сложность операций
* В **сбалансированном** дереве (ветви примерно одинаковой длины) поиск, вставка и удаление занимают **O(log n)**.
* В **вырожденном** дереве (например, если вставлять элементы по возрастанию: 1, 2, 3, 4, 5) дерево превращается в связный список, и сложность падает до **O(n)**. Чтобы этого избежать, используются сбалансированные деревья (AVL, Красно-черные).

### 3. Обходы дерева
* **In-order (Симметричный):** Левый -> Узел -> Правый. Выводит элементы в **отсортированном порядке**.
* **Pre-order (Прямой):** Узел -> Левый -> Правый.
* **Post-order (Обратный):** Левый -> Правый -> Узел.

### 4. Инженерный вывод: когда использовать?
* **BST (и его сбалансированные версии):** когда нужен быстрый поиск (O(log n)) и при этом важно хранить элементы в **отсортированном порядке** (например, для вывода диапазона значений).
* **Хеш-таблица:** когда нужен максимально быстрый поиск (O(1)), но порядок элементов не важен.

### 5. Применение в разработке
* **Базы данных:** индексы в БД строятся на B-деревьях (разновидность сбалансированных деревьев).
* **Файловые системы:** структура каталогов (папки и файлы).
* **Компиляторы:** синтаксические деревья (AST) для разбора кода.
* **Сетевые маршрутизаторы:** таблицы маршрутизации.

### 6. Базовый синтаксис (std::set и std::map)
В C++ сбалансированные деревья реализованы в `std::set` (только ключи) и `std::map` (ключ-значение). Они хранят элементы отсортированными.
~~~cpp
#include <set>
#include <map>

std::set<int> s = {5, 2, 8, 1};
// При переборе элементы будут в порядке: 1, 2, 5, 8

std::map<std::string, int> ages;
ages["Иван"] = 25;
ages["Мария"] = 30;
// Ключи в map также хранятся отсортированными по алфавиту
~~~

## Практика

В папке `src/` находятся три файла:
* `custom_bst.cpp` — заготовка для **собственной реализации** бинарного дерева поиска.
* `stl_set_map.cpp` — пример решения практической задачи с использованием `std::set` и `std::map`.
* `benchmark_bst.cpp` — замер скорости: **поиск в BST против линейного поиска в векторе**.

Выполните задания из [TASKS.md](TASKS.md), чтобы получить практические результаты.

### Предполагаемые результаты бенчмарков
Поиск в BST занимает **O(log n)** и работает значительно быстрее линейного поиска в массиве (O(n)). Однако на очень больших данных он может уступать хеш-таблице (O(1)), но зато BST хранит элементы отсортированными.
*Вывод:* если нужен быстрый поиск с сохранением порядка — используйте BST (или `std::set`/`std::map`). Если порядок не важен — хеш-таблицу.
