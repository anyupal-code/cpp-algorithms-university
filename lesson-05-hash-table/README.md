## Теория

### 1. Проблема поиска в массиве
Если данные хранятся в обычном массиве или векторе, для поиска нужного элемента (например, по ключу) придется перебрать все элементы. Это операция O(n). При миллионе записей это миллион сравнений. Медленно.

### 2. Идея хеш-таблицы
Хеш-таблица решает эту проблему. Вместо перебора она использует **хеш-функцию**, которая преобразует ключ (например, строку или число) в индекс массива.
1. Есть массив (корзины).
2. Есть ключ (например, "Иван").
3. Хеш-функция превращает "Иван" в число (например, 42).
4. Элемент кладется в ячейку с индексом 42.

При поиске мы снова вычисляем хеш и сразу обращаемся к нужной ячейке. Время доступа — **O(1)**.

### 3. Коллизии
Хеш-функция может выдать одинаковое число для разных ключей (например, и "Иван", и "Мария" дадут 42). Это называется **коллизией**.
Методы разрешения коллизий:
* **Метод цепочек (Chaining):** в каждой ячейке хранится связный список элементов с одинаковым хешем.
* **Открытая адресация:** если ячейка занята, ищем следующую свободную (линейное пробирование).

### 4. Инженерный вывод: когда использовать?
* **Хеш-таблица:** когда нужен быстрый поиск, вставка и удаление по ключу за O(1). Идеально для кэшей, словарей, подсчета частоты слов.
* **Массив/Вектор:** когда важен порядок элементов или нужен доступ по индексу.

### 5. Применение в разработке
* **Базы данных:** индексы в PostgreSQL/MySQL построены на хеш-таблицах и деревьях.
* **Кэширование:** Redis, Memcached хранят данные в памяти в виде хеш-таблиц.
* **Проверка уникальности:** проверка email при регистрации (есть ли уже такой в базе).
* **Подсчет частоты:** в компиляторах, анализе текста, логах.

### 6. Базовый синтаксис (std::unordered_map)
В C++ стандартная хеш-таблица — это `std::unordered_map` (ключ-значение) или `std::unordered_set` (только ключи).
~~~cpp
#include <unordered_map>

std::unordered_map<std::string, int> ages;
ages["Иван"] = 25;
ages["Мария"] = 30;

if (ages.find("Иван") != ages.end()) {
    std::cout << "Возраст: " << ages["Иван"] << std::endl;
}
~~~

## Практика

В папке `src/` находятся три файла:
* `custom_hash_table.cpp` — заготовка для **собственной реализации** хеш-таблицы (метод цепочек).
* `stl_hash_table.cpp` — пример решения практической задачи с использованием `std::unordered_map`.
* `benchmark_hash.cpp` — замер скорости: **поиск в хеш-таблице против линейного поиска в векторе**.

Выполните задания из [TASKS.md](TASKS.md), чтобы получить практические результаты.

### Предполагаемые результаты бенчмарков
Поиск в хеш-таблице (`std::unordered_map`) работает за **O(1)** и занимает микросекунды. Линейный поиск в векторе (`std::find`) работает за **O(n)** и на массиве из 100 000 элементов занимает заметное время. 
*Вывод:* для поиска по ключу всегда используйте хеш-таблицы, а не массивы.
